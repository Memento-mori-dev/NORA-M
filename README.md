# Vite-сборщик для вёрстки

Исходная страница — `index.html`, стили подключаются из `src/styles/main.scss`. Главная подключает `src/pages/index.js`, который импортирует общий JavaScript из `src/main.js`.

[Практический гайд на примере двух страниц](GUIDE.md)

## Чистая сборка

Для базовой сборки нужны npm и Node.js `20.19+` в ветке 20 либо Node.js `22.12+`. Используется Vite 8. Проверено на Windows с Node.js `24.18.0` и npm `11.16.0`. Зависимости устанавливаются из `package-lock.json`.

Выполни команды из папки проекта.

```sh
npm ci
npm run build
```

- `npm run dev` запускает сервер для вёрстки с обновлением страницы при изменениях.
- `npm run build` проверяет локальные ссылки и создаёт `dist/`. Отсутствующая страница, файл или якорь останавливают сборку. В сообщении указаны файл, строка и адрес.
- `npm run preview` показывает содержимое `dist/` через локальный HTTP-сервер. Сначала выполни сборку.

При установке с нуля нужен доступ к реестру npm. Глобальная установка Vite, Sass, Sharp и плагинов не требуется. Для проекта также не нужны `.env`, сервер приложений или база данных.

Для чистой сборки достаточно исходников, конфигурации и файлов зависимостей. `node_modules/`, `.venv/`, `dist/` и `src/fonts/generated/` создаются локально. Варианты изображений кешируются в `node_modules/.cache/responsive-images/`.

## Сборка для CMS

`npm run build-cms` собирает оболочку сайта и блоки главной в `dist-cms/`. Для обычной сборки сайта по-прежнему используется `npm run build`.

- `index/index.html`, `index/index.css` и `index/index.js` содержат оболочку, хедер, меню каталога, футер и общие стили.
- `blocks/<имя>/block.html` содержит готовый HTML-фрагмент. Рядом лежит `block.css` и, у интерактивных блоков, `block.js`.
- `assets/` содержит общие зависимости, изображения, шрифты и SVG-спрайт.
- `manifest.json` перечисляет оболочку и блоки в порядке главной. Поле `html` — путь к файлу внутри сборки, `css` и `js` — списки URL для подключения в браузере.

Опубликуй содержимое `dist-cms/` в корне сайта или задай `CMS_BASE` перед сборкой. Например, для публикации под `/static/nora/` в PowerShell выполни `$env:CMS_BASE = '/static/nora/'`, затем `npm run build-cms`.

На сервере CMS загрузи оболочку и замени комментарий `<!-- CMS_BLOCKS -->` содержимым выбранных HTML-фрагментов. CSS и JS оболочки уже подключены в её HTML. Добавь ссылки на CSS блоков после стилей оболочки, а их JS подключи как модули. Каждый файл подключается один раз. Скрипты и разметка рассчитаны на один экземпляр каждого блока на странице. При использовании оболочки на вложенных страницах задай ссылке логотипа URL главной в шаблоне CMS.

Чтобы сохранить общую серую подложку для «Линеек брендов» и «Партнёров», вставь эти два фрагмента в одну обёртку с классом `brand-showcase`. Обёртка оптового баннера уже входит в его фрагмент.

## Если в проекте есть локальные шрифты

Python нужен, когда в `src/fonts/` есть исходные файлы `.ttf`, `.otf`, `.woff` или `.woff2`. Для FontTools требуется Python `3.11+`. Проверено с Python `3.14.4` и FontTools `4.68.0`.

Один раз установи зависимости в отдельное виртуальное окружение. В Windows выполни команды из папки проекта.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-fonts.txt
```

На macOS и Linux используй `python3 -m venv .venv` и `.venv/bin/python -m pip install -r requirements-fonts.txt`.

`npm run dev` и `npm run build` автоматически запускают `npm run fonts`. Скрипт сам находит `.venv`, поэтому активировать окружение не требуется. Если добавишь шрифт при работающем dev-сервере, запусти `npm run fonts` отдельно. Подключи нужное начертание через `helpers.font-face()` в `src/styles/_fonts.scss`. Подключённые WOFF и WOFF2 попадут в `dist/assets/fonts/`.

## Что работает

| Возможность | Как пользоваться |
| --- | --- |
| HTML-фрагменты Handlebars | Положи `.html` или `.hbs` в `src/partials/` и вставь `{{> имя}}` в страницу. Фрагмент можно вызывать с параметрами. |
| JavaScript страниц | Создай модуль для страницы в `src/pages/`, импортируй `../main.js` и подключи модуль в HTML. При сборке общий код и код страниц идут в разные файлы в `assets/js/`. |
| Адаптивные размеры в SCSS | Используй `helpers.phone-vw()` и `helpers.desktop-vw()`. Настройки находятся в `src/styles/helpers/_adaptive.scss`. Текущий переход к десктопу — `768 px`, ширина мобильного макета — `390 px`, предел масштабирования на десктопе — `1600 px`. |
| CSS и Dynamic Adapt | Vite собирает стили и медиаправила каждой HTML-страницы в отдельный минифицированный CSS. `data-da` без собственного порога использует `$desktop-min-width` из Sass через CSS-переменную. Порог в пикселях можно задать вручную в `data-da`. |
| Адаптивные изображения | Добавь `data-responsive` и `width` к локальному PNG или JPEG в `<img>`. Плагин создаёт `<picture>` с AVIF и WebP в ширинах `0.5×`, `1×`, `1.5×`, `2×`, пропуская размеры крупнее исходника. Исходный PNG или JPEG остаётся запасным вариантом. `sizes` можно задать в HTML. |
| WebP в SCSS | Подключи локальный PNG или JPEG через `url('/src/images/hero.jpg?webp')`. Сборщик подставит один WebP без ресайза. |
| SVG-спрайт | Положи иконки в `src/icons/` и подключай обычным `<img>`. Подходящие ссылки преобразуются в `<svg><use>`. Самостоятельные SVG-иллюстрации храни за пределами `src/icons/`. |
| Веб-шрифты | Положи исходник в `src/fonts/`. FontTools подготавливает недостающие форматы, а готовые WOFF и WOFF2 копируются как есть. |

Примеры разметки и ограничения плагинов есть в [AGENTS.md](AGENTS.md).

## Проверка SVG-спрайта

На машине нужны установленные зависимости проекта и Chrome или Chromium. После `npm ci` выполни следующую команду из той же папки.

```sh
npm run check:svg
```

1. Сценарий создаёт тестовую страницу с исходными SVG и теми же иконками из спрайта во временной папке.
2. В dev и production проверяет, что спрайт загружается, а все ссылки `<use>` ведут на существующие символы.
3. Сравнивает отрисовку в Chrome. Проверяются градиенты, порядок заливки в `style`, одинаковые ID в разных иконках, маска, `clip-path`, фильтр и `currentColor`.

Успешный запуск выводит по 7 проверенных иконок для dev и production. При ошибке команда возвращает ненулевой код и указывает режим и проблемный случай. Временные файлы удаляются после проверки. Если браузер установлен в другом месте, укажи полный путь в переменной окружения `CHROME_BIN`.

## Что попадает в `dist/`

```text
dist/
├── index.html
└── assets/
    ├── css/
    ├── js/
    ├── images/
    ├── svg/
    ├── fonts/
    └── other/
```

Папки создаются по мере появления файлов. По умолчанию входная страница одна — `index.html`. Чтобы собрать дополнительные страницы, добавь их в `build.rolldownOptions.input` в `vite.config.js`. Файлы для копирования с сохранением имени клади в нужную подпапку `public/assets/`. Для публикации нужен каталог `dist/`.

## Результат проверки

Базовая сборка прошла в отдельной папке после `npm ci`, без `.venv` и ранее созданных файлов. После установки FontTools сборка тестовой страницы подготовила WOFF и WOFF2 из TTF. Через `preview` проверены подстановка Handlebars, четыре ширины AVIF и WebP для PNG и JPEG, отдельный SVG, спрайт и оба шрифта. На dev-сервере проверены шаблон, адаптивные изображения и спрайт.

Текущий `index.html` — стартовый шаблон. CI пока не настроен.
