# Работа с шаблонами, изображениями и шрифтами

Команды npm запускаются из корня проекта, где находится `package.json`.

## Структура сборки

Готовые HTML-страницы лежат в `dist/` по путям входных страниц. Подключённые файлы сборка раскладывает по категориям внутри `dist/assets/`:

- `css/` — отдельные минифицированные файлы стилей для HTML-страниц.
- `js/` — JavaScript.
- `images/` — растровые изображения, включая варианты AVIF и WebP.
- `svg/` — отдельные SVG и общий спрайт.
- `fonts/` — шрифты.
- `other/` — остальные импортированные ассеты.

Подключай исходники из `src/`, чтобы Vite сам выбрал папку и обновил ссылки при сборке. Если файл должен копироваться как есть, положи его в подходящую подпапку `public/assets/`: Vite сохраняет путь относительно `public/`.

### Проверка локальных ссылок

`npm run build` завершится ошибкой, если в собранных HTML или CSS есть ссылка на отсутствующий файл или якорь. Плагин проверяет локальные переходы, `src`, `srcset`, SVG-спрайт и CSS `url()`, в том числе внутри CSS-переменных. Ошибка указывает файл, строку и значение ссылки. Внешние URL, `mailto:` и `tel:` пропускаются. Для дополнительной HTML-страницы добавь входную точку в `build.rolldownOptions.input`. При нестандартном `base` ссылки должны вести в каталог публикации.

В `@supports` проверяются ресурсы внутри блока стилей. Якорь внутри `<template>` доступен при проверке ссылок из того же шаблона, а для ссылок со страницы нужен якорь в её HTML вне шаблона.

## UI Kit

Перед вёрсткой проверь, есть ли в UI Kit проекта нужные элементы и варианты компонентов. Если есть подходящий компонент, переиспользуй его реализацию из проекта.

## HTML-шаблоны Handlebars

Храни общие блоки в [src/partials/](src/partials/) как файлы `.hbs` или `.html`. Например, `header.html` подключается в HTML-странице Vite через `{{> header }}`.

Для блока с параметрами создай `src/partials/button.hbs`:

```handlebars
<a class="button" href="{{href}}">{{label}}</a>
```

Подключай его с нужными значениями в `index.html` или другой входной HTML-странице:

```handlebars
{{> button href="/catalog.html" label="Каталог" }}
{{> button href="/contacts.html" label="Контакты" }}
```

При `npm run dev` и `npm run build` Handlebars разворачивает фрагменты в обычный HTML. При правке подключённого фрагмента dev-сервер обновляет страницу.

Плагин стоит первым в [vite.config.js](vite.config.js), поэтому SVG-спрайт и `data-responsive` работают и внутри фрагментов. Для ассетов, которые используются на страницах в разных папках, указывай пути от корня Vite, например `/src/icons/search.svg`.

## Семантика ссылок и кнопок

Выбирай HTML-элемент по действию, независимо от его внешнего вида.

- Используй `<a href="…">` для перехода на другую страницу, к разделу текущей страницы или к ресурсу. Ссылками также остаются скачивание файла, `tel:` и `mailto:`.
- Используй `<button type="button">` для действий в интерфейсе: открыть или закрыть меню, раскрыть список, очистить поле или переключить состояние. Для отправки формы используй `<button type="submit">`.
- Не подменяй действие ссылкой с фиктивным `href` или `role="button"`. Если элемент ничего не делает, оставь его обычным текстом.


## JavaScript страниц

Для каждого интерактивного блока создавай отдельный JS-модуль в src/script/ и подключай его из точки входа страницы или общего src/main.js. Логику частей одного блока можно размещать в отдельных модулях и подключать через модуль этого блока. Общие утилиты и анимации храни в отдельных модулях и импортируй там, где они нужны. Для блока без JavaScript пустой файл не нужен.

В [src/main.js](src/main.js) подключай модули общих блоков и запускай общую инфраструктуру. Для отдельной страницы создай модуль в `src/pages/` и импортируй из него общий код. Например, начало `src/pages/catalog.js`.

```js
import '../main.js';
```

Добавь код каталога в этот модуль и подключи его в HTML каталога.

```html
<script type="module" src="/src/pages/catalog.js"></script>
```

Для новой страницы добавь её HTML в `build.rolldownOptions.input` в `vite.config.js`. В сборке общий код попадает в `dist/assets/js/common.js`, а код страницы — в отдельный файл рядом. Если модуль страницы содержит только импорт общего JS, Vite подключает `common` напрямую.

## Слайдеры

Для слайдеров используй Swiper. Подключай JavaScript и CSS из локальной сборки в [src/vendor/swiper/](src/vendor/swiper/) на страницах, где нужен слайдер. Настройки и инициализацию храни в JS-модуле соответствующего блока.

## Размеры в SCSS через `rem()`

Фиксированные длины из макета записывай через `rem()`. Это размеры блока и шрифта, отступы, `gap`, радиусы, толщины границ и контуров. Функция объявлена в [`src/styles/helpers/_functions.scss`](src/styles/helpers/_functions.scss) и экспортируется модулем `helpers`.

- Передавай число из макета без единицы измерения. Sass делит его на 16 и добавляет `rem`: `helpers.rem(16)` → `1rem`, `helpers.rem(24)` → `1.5rem`. Дробные и отрицательные числа тоже допустимы. Вызов `helpers.rem(16px)` останавливает сборку с ошибкой.
- `rem` в браузере зависит от размера шрифта корневого элемента `html`. При корневом размере 16 px значение `1.5rem` равно 24 px. Сохраняй корневой размер шрифта по умолчанию, чтобы вёрстка учитывала настройки браузера.
- Оставляй без преобразования проценты, `fr`, `vw`, ключевые слова, нулевые длины и безразмерные значения вроде `line-height: 1.4`. В `min()`, `max()`, `clamp()` и CSS-переменных переводи только фиксированные длины из макета. В CSS-переменных используй интерполяцию `#{helpers.rem(24)}`. Вычисления Sass делай над числами до вызова `rem()`: текущая реализация возвращает строку с CSS-длиной.
- Для смены размеров на брейкпоинте используй существующие миксины `helpers.mobile` и `helpers.mobile-above`.

Пример для файла в `src/styles/blocks/`. Из файла непосредственно в `src/styles/` подключай `@use 'helpers' as helpers;`.

```scss
@use '../helpers' as helpers;

.product-card {
  width: min(100%, helpers.rem(342));

  padding: helpers.rem(12) helpers.rem(16);

  display: grid;
  gap: helpers.rem(8);

  border-radius: helpers.rem(20);

  font-size: helpers.rem(14);
  line-height: 1.4;

  @include helpers.mobile-above {
    padding: helpers.rem(24);

    gap: helpers.rem(16);
  }
}
```

## CSS-переходы

Для CSS-переходов по умолчанию используй `var(--transition-easing)`. Переменная определена в `src/styles/_variables.scss` и содержит `cubic-bezier(0.22, 1, 0.36, 1)`. Если для конкретного перехода указана другая кривая, используй её. В сокращённой записи `transition` указывай переменную для каждого свойства.

```scss
transition: background-color var(--transition-duration) var(--transition-easing);
```

## Адаптивные стили и Dynamic Adapt

Пиши стили всех диапазонов блока в одном SCSS-файле. Общие и мобильные значения задай по умолчанию. Подключай стили блоков через [main.scss](src/styles/main.scss).

**Размеры шрифтов.** На ПК, планшетах и телефонах задавай фиксированный `font-size` через `helpers.rem()` для каждого диапазона ширины. Меняй размер только на брейкпоинте, если в соответствующем макете Figma задан другой размер или если текст не помещается после адаптации раскладки. Если текст не помещается, подбери брейкпоинт и задай меньший фиксированный размер для узкого диапазона. Для `font-size` не используй плавную привязку к ширине окна или контейнера, в том числе `vw`, `cqw`, `clamp()` с переменной шириной, `helpers.fluid-text()` и `helpers.phone-vw()`.

- **ПК, выше 1600 px.** Используй `helpers.laptop-above` и фиксированные размеры из макета через `helpers.rem()`. Максимальная ширина центрированного контейнера — `120rem` (1920 px при корневом размере 16 px). Выше этой ширины макет больше не растёт.
- **Планшет, 768–1600 px включительно.** Используй `helpers.tablet-layout`. Размеры шрифтов, элементов и отступов бери из макета и задавай через `helpers.rem()`. Адаптируй вёрстку прежде всего перестроением сетки. Например, меняй число колонок или расположение элементов. Для сложной сетки используй CSS Grid. Крупные изображения, которые занимают значительную часть экрана, подстраивай под ширину контейнера, сохраняя пропорции.
- **Мобильная версия, ниже 768 px.** Используй мобильные базовые стили или `helpers.mobile`. Для пропорциональных размеров элементов и отступов используй `helpers.phone-vw()` с числом из макета на 390 px. `helpers.mobile-above` охватывает планшеты и ПК, начиная с 768 px.
- Общие границы и ширины макетов заданы в [_adaptive.scss](src/styles/helpers/_adaptive.scss). Vite собирает стили и медиаправила каждой HTML-страницы в её таблицу. Подключай базовый CSS Swiper перед стилями блоков в main.scss, чтобы порядок каскада совпадал в dev и сборке.
- `data-da=".mobile-target"` переносит элемент по той же границе, что использует `helpers.mobile`. Если нужен отдельный порог, внутри атрибута задай его в пикселях, например `data-da=".mobile-target, 600, first"`.

**Переносы строк.** Если по макету нужен перенос строки в конкретном месте, используй `<br>`. Если перенос нужен только на определённом размере экрана, используй общий класс проекта: `<br class="br-mobile">` для телефона или `<br class="br-desktop">` для компьютера. Применяй перенос только в соответствующем диапазоне проекта: `helpers.mobile` для телефона и `helpers.laptop-above` для компьютера. За пределами этого диапазона скрывай `<br>`. Определяй классы один раз в общих стилях и переиспользуй их во всех блоках. Если естественный перенос совпадает с макетом, `<br>` не нужен.

### Справочник по брейкпоинтам

Миксины определены в [_media.scss](src/styles/helpers/_media.scss). Условия проверяют ширину окна. Значения в пикселях указаны для базового размера шрифта браузера 16 px.

| Миксин | Ширина окна | Что делает |
| --- | --- | --- |
| `helpers.laptop-above` | > 1600 px (> 100rem) | Включает десктопную раскладку с фиксированными размерами в `rem()`. |
| `helpers.tablet-layout` | 768–1600 px (48–100rem), обе границы включены | Включает планшетную раскладку. Сетка перестраивается, размеры шрифтов и элементов берутся из макета. |
| `helpers.mobile` | < 768 px (< 48rem) | Включает мобильные переопределения. На этой же границе срабатывает `data-da` без явно заданного порога. |
| `helpers.mobile-above` | ≥ 768 px (≥ 48rem) | Применяет одно правило для гибкой и десктопной раскладок. |
| `helpers.laptop` | ≤ 1600 px (≤ 100rem) | Применяет одно правило для гибкой и мобильной раскладок. |
| `helpers.tablet` / `helpers.tablet-above` | ≤ 1023.98 px / > 1023.98 px (63.99875rem) | Дополнительный порог для отдельных перестроений, например смены числа колонок. |
| `helpers.mobile-s` / `helpers.mobile-s-above` | ≤ 480.98 px / > 480.98 px (30.06125rem) | Дополнительный порог для узких мобильных экранов. Например, в UI Kit `helpers.mobile-s` включает двухколоночную палитру. |

Ширина **1920 px (120rem)** ограничивает рост центрированного контейнера. Ширина **390 px (24.375rem)** задаёт опорный размер для `helpers.phone-vw()`. На этих двух отметках режим раскладки сам по себе не переключается.

## Адаптивные изображения

**Ленивая загрузка изображений.** Для всех изображений вне хедера и первого блока страницы указывай `loading="lazy"` на элементе `<img>`. В хедере и первом блоке оставляй обычную загрузку. Если изображение подключено через `<picture>` или обрабатывается плагином `data-responsive`, ставь атрибут на исходный `<img>` внутри разметки.

Пропускай локальные PNG и JPEG через плагин оптимизации изображений проекта. Для адаптивных изображений добавь к `<img>` атрибут `data-responsive` и укажи базовую ширину в `width` целым числом в пикселях. Укажи `height` и `alt` как в обычной вёрстке.

```html
<img
  src="./src/images/mountains.jpg"
  width="800"
  height="450"
  loading="lazy"
  data-responsive
  alt="Горы на рассвете"
>
```

- В dev-режиме плагин обрабатывает изображения при открытии HTML-страницы. При сборке Vite записывает готовые варианты в `dist/assets/images/`. Имена вариантов содержат исходное имя, ширину и качество, например `closers-678w-q80.webp`.
- Плагин подставляет `<picture>` с AVIF и WebP и сохраняет исходный `<img>` как запасной вариант. Множители ширины — `0.5×`, `1×`, `1.5×` и `2×`. Для `width="800"` это 400, 800, 1200 и 1600 px, если исходник достаточно большой.
- Sharp сохраняет пропорции. Плагин пропускает варианты крупнее исходника. Если исходник меньше всех запрошенных вариантов, плагин использует его собственную ширину.
- Если изображение занимает только часть окна, задай `sizes` на исходном `<img>` по реальной ширине блока. Плагин перенесёт это значение в элементы `<source>`.
- Форматы, качество и множители задаются в [vite.config.js](vite.config.js). Обработка HTML и файлов находится в [responsive-images.js](plugins/responsive-images.js).

### WebP для изображений фиксированного формата

Если изображению достаточно одного варианта, добавляй `?webp` к пути локального PNG или JPEG в `<img src>`, импорте JavaScript или `url()` в SCSS. Для вложенных SCSS-файлов указывай путь от корня Vite. Готовые WebP, AVIF и векторные SVG подключай напрямую.

```scss
.hero {
  background-image: url('/src/images/hero.jpg?webp');
}
```

В dev и при сборке этот адрес ведёт на один WebP без ресайза. Качество берётся из настройки `formats.webp` в [vite.config.js](vite.config.js). При сборке файл попадает в `dist/assets/images/`. Обычный `url()` подключает исходное изображение. Для HTML-картинок с вариантами ширины и формата используй `<img data-responsive>` из раздела выше.

## SVG-спрайт

Клади SVG-иконки для общего спрайта в [src/icons/](src/icons/). Подпапки поддерживаются. В исходном HTML ссылайся на SVG через обычный `<img>`.

```html
<img src="./src/icons/search.svg" class="icon icon-search" width="24" height="24" alt="">
```

- При `npm run dev` и `npm run build` Vite собирает все SVG из `src/icons/` в общий спрайт. В итоговом HTML ссылки на эти файлы из обычных `<img>` преобразуются в `<svg><use></use></svg>`. В сборке спрайт лежит в `dist/assets/svg/icons.svg`.
- Классы и размеры переносятся на внешний `<svg>`. Содержательный `alt` задаёт доступное имя. Используй `alt=""` для декоративных иконок. Стили привязывай к классу, например `.icon-search`.
- Для цвета из CSS укажи `fill="currentColor"` или `stroke="currentColor"` в SVG и меняй `color` через класс. Явные цвета в исходных SVG сохраняются.
- Ссылки `url(#id)` из корневой заливки, обводки, маски, фильтра или `clip-path` остаются внутри спрайта вместе с определениями. Это работает и для соответствующих свойств в корневом `style`.
- Храни самостоятельные SVG-иллюстрации за пределами `src/icons/`. Преобразование применяется к обычным ссылкам на файлы `.svg` из этой папки. Встроенный SVG, `<picture>` и `<img>` с `srcset` или `usemap` сохраняют свою разметку.
- Настройки спрайта находятся в [vite.config.js](vite.config.js), замена HTML — в [svg-sprite-images.js](plugins/svg-sprite-images.js). Плагину требуется Node.js `20.19+`.

## Подготовка шрифтов

Клади исходные `.ttf`, `.otf`, `.woff` или `.woff2` непосредственно в [src/fonts/](src/fonts/). Используй одинаковое имя без расширения для разных форматов одного начертания. Например, `Manrope-Regular.ttf` и `Manrope-Regular.woff2` относятся к одному начертанию.

- `npm run fonts` подготавливает оба веб-формата в `src/fonts/generated/`. Готовые файлы WOFF и WOFF2 копируются как есть, недостающий формат создаёт FontTools.
- `npm run dev` и `npm run build` автоматически запускают эту команду перед Vite. Если шрифт добавлен во время работы dev-сервера, запусти `npm run fonts` отдельно.
- Для конвертации используется Python с зависимостями из [requirements-fonts.txt](requirements-fonts.txt). На новом компьютере создай виртуальное окружение `.venv` и установи в него зависимости из этого файла.

Зарегистрируй каждое начертание в [_fonts.scss](src/styles/_fonts.scss). Этот файл уже подключает общий модуль `helpers`. Передавай имя файла без расширения.

```scss
@include helpers.font-face('Manrope', 'Manrope-Regular', 400);
@include helpers.font-face('Manrope', 'Manrope-Bold', 700);
```

Миксин указывает WOFF2 первым и WOFF вторым. Для основного шрифта страницы задай семейство в `--font-family` в [_variables.scss](src/styles/_variables.scss).

При изменении обработки ассетов проверь `npm run build` и ссылки на сгенерированные файлы. Храни исходники и настройки в репозитории. Кеш изображений, `src/fonts/generated/` и `dist/` создаются командами проекта.
